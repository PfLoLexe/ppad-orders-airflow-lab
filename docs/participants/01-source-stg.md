# Участник 1: генератор и слой STG

## Ответственность

Подготовить источник заказов, описать формат и загрузить исходные данные в STG. Передать участнику 2 манифест, описание полей и правила изменений. Этот документ распределяет работу для защиты; он не утверждает, что конкретный студент уже выполнил её лично.

## Что реализовано

- `orders_lab/generator.py`: генератор покупателей, товаров, заказов и ежедневных снимков.
- `data/reference/catalog.json`: утверждённые названия и учебные цены 30 товаров.
- `data/reference/*_source.json`: сохранённые референсы имён и фамилий.
- `orders_lab/validation.py`: проверка структуры, связей, сумм и времени.
- `orders_lab/pipeline.py`, функция `load_stg`: контрольные суммы, исходный JSON и журнал этапов.
- `tests/test_generator.py`: воспроизводимость, история цен, статусы и отрицательные сценарии.

## Формат источника

Один JSON на день содержит `meta`, `categories`, `customers`, `products`, `orders`. В заказ вложены позиции с `line_no`, `product_id`, `quantity`, `unit_price`. День наблюдения — `snapshot_date`; граница видимых событий — `observed_before`. Это полный накопительный снимок, поэтому один заказ встречается в нескольких файлах.

`manifest.json` содержит параметры генератора, `dataset_id`, список файлов и SHA-256 каждого. STG хранит JSON целиком и не исправляет бизнес-данные. Проверка бизнеса выполняется перед DDS: при ошибке исходник остаётся доступен в STG.

## Команды для демонстрации

```bash
python3 -m orders_lab.generator --catalog data/reference/catalog.json
python3 -m unittest discover -s tests -v
sudo docker compose exec -T airflow python -m orders_lab.pipeline stg
sudo docker compose exec postgres psql -U postgres -d warehouse
```

Для SQL с кавычками удобнее открыть psql и выполнить:

```sql
SELECT snapshot_date, jsonb_array_length(payload->'orders') AS orders_count
FROM stg.snapshots ORDER BY snapshot_date;
```

## Что объяснить на защите

Почему нужен seed; почему цена хранится десятичной строкой; почему повторения заказов в снимках не являются новыми продажами; как SHA-256 обнаруживает подмену; зачем STG сохраняет исходный документ. Показать ФИО в российском порядке и два изменения цены товара 1. Указать, что цены учебные, а данные покупателей вымышлены.

## Передача следующему участнику

Передаются стабильные идентификаторы, ежедневные снимки по порядку и правила статусов. DDS не должен загружать последний файл первым: промежуточная история отсутствует в одном снимке. Контракт и метрики описаны в [предметной области](../domain.md).
