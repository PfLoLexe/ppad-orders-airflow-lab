# Участник 3: витрины CDM и BI

## Ответственность

Подготовить витрины из DDS, зафиксировать определения метрик и построить дашборд. Сверить BI с исходными заказами и объяснить влияние фильтров.

## Что реализовано

- `sql/02_cdm.sql`: исторические срезы заказов и позиций, дневные агрегаты.
- `orders_lab/pipeline.py`: `load_cdm`, проверки CDM.
- `scripts/metabase_bootstrap.py`: подключение PostgreSQL, коллекция, 12 вопросов, дашборд и фильтры.
- `reports/metabase-artifacts.json`: идентификаторы созданных объектов после запуска.
- `reports/metabase-results.json`: результаты выполненных запросов после запуска.

CDM читает исключительно DDS. BI-роль `bi_reader` имеет доступ к схеме CDM. Она не читает STG, DDS и служебные базы приложений.

## Метрики и фильтры

Полные определения находятся в [описании предметной области](../domain.md). Ключевые различия: оформленная сумма включает отменённые заказы; доставленные продажи учитывают только `delivered`; средний чек считается по заказам, а не по строкам позиций. Доля отмен относится к когорте заказов по дате оформления и состоянию на выбранный срез.

Период для продаж, среднего чека, срока и топов применяется к дате доставки. Для количества заказов, оформленной суммы и отмен — к дате оформления. При выбранной категории суммы ограничиваются позициями этой категории; чек относится к заказам, содержащим такие позиции. Пустые фильтры означают весь период, все города и категории, последний срез.

## Команды для демонстрации

```bash
sudo docker compose exec -T airflow python -m orders_lab.pipeline cdm
sudo docker compose exec -T airflow python -m orders_lab.pipeline check-cdm
python3 scripts/metabase_bootstrap.py
```

Открыть Metabase по адресу из README, коллекцию «Лабораторная — заказы», дашборд «Заказы интернет-магазина». Сначала показать общий срез, затем выбрать город, категорию и более раннюю дату. В таблице заказов найти строки, объясняющие агрегированные значения. Нажатие на заголовок вопроса открывает его запрос и подробные результаты.

## Контрольный SQL

```sql
SELECT count(*) AS orders, sum(order_amount) AS ordered_rub,
       sum(order_amount) FILTER (WHERE status_code='delivered') AS sales_rub,
       round(avg(order_amount) FILTER (WHERE status_code='delivered'),2) AS average_check_rub
FROM cdm.order_snapshots
WHERE snapshot_date=(SELECT max(snapshot_date) FROM cdm.order_snapshots);
```

## Что объяснить на защите

Почему нельзя суммировать все срезы; почему JOIN с позициями может исказить средний чек; как восстановить прошлый статус после загрузки будущего дня; почему дата доставки и дата оформления дают разные графики; как избежать деления на ноль. Показать, что графики и вопросы читают CDM и используют единые фильтры.
