# Увеличение числа записей и другие параметры

Генератор создаёт фиксированный набор с полными ежедневными снимками. `--orders` задаёт число заказов за весь период, а не за сутки. Каждый заказ содержит от одной до четырёх разных позиций, каждая — от одной до трёх единиц товара. Новые снимки показывают появление заказов, смену статусов и цен.

## Параметры генератора

| Параметр | По умолчанию | Смысл и ограничения |
| --- | --- | --- |
| `--orders` | `1000` | Заказы за период; минимум 3 |
| `--customers` | `100` | Покупатели; минимум 1. При большом числе ФИО могут повторяться, идентификаторы уникальны |
| `--days` | `30` | Число последовательных дней; минимум 4 |
| `--start-date` | `2026-09-01` | Первый день в формате `YYYY-MM-DD` |
| `--seed` | `42` | Seed псевдослучайного генератора для воспроизводимости |
| `--products` | `30` | Товары из каталога; от 1 до 30 в текущем каталоге |

Чтобы расширить ассортимент сверх 30, сначала добавьте товары с уникальными идентификаторами и корректными категориями в `data/reference/catalog.json`. Цены задаются строками с двумя знаками после точки. Каталог должен иметь статус `approved`; его содержимое участвует в идентификаторе набора.

Изменение параметров или каталога создаёт другой `dataset_id`. Новый набор нельзя загрузить в warehouse со старым набором. Это проверяется загрузчиком и `configure.py`. Простая правка `.env` не превращает один набор в другой.

## Новый стенд на 10 000 заказов: Linux / macOS

Если старый стенд уже запущен, в его папке выполните:

```bash
docker compose stop
```

Его тома и данные сохранятся. В другой папке создайте новую копию:

```bash
git clone https://github.com/PfLoLexe/ppad-orders-airflow-lab.git orders-lab-large
cd orders-lab-large
COMPOSE_PROJECT_NAME=orders-lab-large bash scripts/start.sh \
  --orders 10000 --customers 1000 --days 30 --seed 42
```

Скрипт выбирает созданный manifest явно, поэтому наличие эталонных снимков в репозитории не мешает. Он сохраняет имя `orders-lab-large` в новом `.env`. Compose создаёт отдельные тома этого проекта; порты остаются прежними, поэтому старый и новый экземпляры по этой инструкции запускаются по очереди.

Последующие команды в новой папке работают с новым проектом:

```bash
docker compose ps
docker compose stop
docker compose start
```

Для повторного полного запуска используйте те же параметры:

```bash
bash scripts/start.sh --orders 10000 --customers 1000 --days 30 --seed 42
```

Запуск без параметров в этой папке попытается выбрать стандартный набор и будет отклонён. Для возврата к старому стенду остановите новый через `docker compose stop`, перейдите в старую папку и выполните `docker compose start`.

## Новый стенд на 10 000 заказов: PowerShell

Остановите старый экземпляр из его папки через `docker compose stop`. Затем:

```powershell
git clone https://github.com/PfLoLexe/ppad-orders-airflow-lab.git orders-lab-large
cd orders-lab-large
$env:COMPOSE_PROJECT_NAME = 'orders-lab-large'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 `
  -Orders 10000 -Customers 1000 -Days 30 -Seed 42
Remove-Item Env:COMPOSE_PROJECT_NAME
```

Имя проекта сохранено в `.env`. В последующих терминалах достаточно `docker compose start` из этой папки. Остальные параметры PowerShell: `-Products`, `-StartDate`.

## Только файлы источника

```bash
python3 -m orders_lab.generator --catalog data/reference/catalog.json \
  --orders 10000 --customers 1000 --start-date 2026-08-01 --days 12 --seed 7
```

Команда печатает путь к manifest и создаёт отдельную папку в `data/snapshots/`. Контейнеры и `.env` при этом не меняются. Если продолжаете ручной запуск в новой копии проекта, передайте напечатанный путь:

```bash
python3 scripts/configure.py --manifest data/snapshots/ИМЯ_НАБОРА/manifest.json
docker compose up -d --wait --wait-timeout 360
docker compose exec -T airflow airflow dags trigger orders_pipeline
```

После состояния `success` выполните `python3 scripts/metabase_bootstrap.py`, проверку warehouse внутри Airflow и `python3 scripts/verify_bi.py`, как в README. Для обычного использования удобнее полный `start.sh` или `start.ps1`: они выполняют эту последовательность автоматически.

## Что меняется при росте объёма

DDS содержит каждый заказ и его позиции один раз, а также версии статусов. STG сохраняет полные снимки. CDM содержит исторические срезы заказов и позиций: один заказ присутствует в каждом срезе после своего появления. Поэтому число строк CDM может значительно превышать `--orders`, а место под JSON и время обработки растут вместе с числом заказов и дней.

Дашборд по умолчанию показывает последний срез. В фильтре «Дата среза» можно посмотреть более ранний день. Метрики доставок используют дату доставки, метрики оформленных заказов и отмен — дату оформления; последние заказы могут ещё не успеть доставиться к концу периода. Эти правила подробно описаны в `docs/domain.md`.

Лимиты контейнеров автоматически не увеличиваются. Для оценки ресурсов используйте `docker stats --no-stream` и размер `data/snapshots/`. Если DAG ещё работает, состояние `running` само по себе не означает ошибку. Скрипт ожидает DAG около десяти минут плюс время команд опроса; при превышении ожидания проверьте Airflow и после успешного окончания выполните настройку Metabase и проверки вручную.

## Типичные ошибки

| Сообщение / симптом | Что сделать |
| --- | --- |
| `.env настроен на другой набор` | Создать новую копию и отдельное имя Compose-проекта; не менять manifest в заполненной БД |
| `Найдено несколько наборов` | Передать `configure.py --manifest` точный путь; полный скрипт делает это сам |
| Порт уже занят | Остановить другой стенд, использующий 8080, 3333 или 15432 |
| Новый пароль из `.env` не работает | Существующий том сохранил старые роли и пароли; восстановить настройки или провести явную смену пароля в БД |
| Новый набор отклонён в DDS | Проверить выбранный manifest и отдельное имя Compose-проекта; чужие тома не удалять |
